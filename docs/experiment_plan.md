# Експеримент: план і очікування до замірів

> Коміт цього файлу передує запускам експерименту. Гіпотеза - із заявки, без змін;
> нижче - що очікуємо, виходячи з оцінок (`docs/estimates.md`) і доказового запуску
> (`docs/phase_map_full.md`, P = 32).

## Гіпотеза (заявка, крок 5)

Змінюємо лише `spark.sql.shuffle.partitions`: 8 проти 32 (AQE вимкнено). 32 розділи
зменшать медіанний час щонайменше на 15% порівняно з 8, а обсяг записаних shuffle-даних
зміниться не більш ніж на 10%.

## Що змінює P, а що ні

* Stage A (17 задач, читання 2,19 ГБ CSV, очищення, часткова агрегація етапу 1) від P
  не залежить: кількість його задач задає розбиття CSV (128 MiB), а не P.
* Від P залежать лише stage B (P задач: фінал етапу 1 + часткова агрегація етапу 2)
  і stage C (P задач: фінал етапу 2) та обсяг shuffle 2.

## Очікування за доказовим запуском (P = 32)

| Величина | P = 32 (факт) | P = 8 (очікування) | Як отримано |
|---|---|---|---|
| Stage A, с | 29,7 | ≈ 29,7 | не залежить від P |
| Stage B + C, с | 0,97 | ≈ 0,5–1,0 | менше задач, але кожна більша; разом < 1 с |
| Job analysis, с | 30,7 | ≈ 30 | частка stage A = 97% |
| Shuffle 1, записи | 1 761 900 | 1 761 900 | залежить лише від map-задач stage A |
| Shuffle 2, записи | 43 404 | ≈ 12 841 | P·(1 − (1 − 1/P)^d) по маршрутах |
| Shuffle 2, байти | 1,6 MiB | ≈ 0,5 MiB | ≈ 76 Б/запис, стиснення ≈ 1,9× як при P = 32 |
| Shuffle разом | ≈ 29,8 MiB | ≈ 28,7 MiB | зміна ≈ 4% |

**Прогноз:** частина гіпотези про час *не підтвердиться*. 32 розділи можуть змінити лише
≈ 1 с з ≈ 31 с (≤ 3%, у межах шуму), а не 15%. Частина про обсяг shuffle
*підтвердиться*: ≈ +4% при переході з 8 на 32 (≤ 10%), хоча shuffle 2 окремо зросте
приблизно в 3,4 раза.

## Протокол

`docker compose run --rm tools scripts/run_experiment.py --input full --runs 3`:
по 1 прогріву кожного варіанта, далі 3 заміри кожного, порядок 8, 32, 8, 32, 8, 32;
кожен запуск - окремий spark-submit без звіту якості; метрики - з журналу подій;
перевірка, що результат усіх запусків однаковий. Умови: ноутбук на зарядці, режим
живлення «найкраща продуктивність», інші важкі програми закриті, Docker Desktop (WSL2),
local[16], driver-memory 4g, дані на диску C: через bind mount.
